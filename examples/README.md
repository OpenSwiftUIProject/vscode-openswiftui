# Hello world examples

Both examples contain the same `ContentView` and `#Preview { ContentView() }`.
They depend on the official OpenSwiftUI-spm `0.24.3` package. Neither contains
preview host sources, a custom macro declaration, or preview JSON configuration.

| Example | Project | Source to open |
| --- | --- | --- |
| [DemoKit](DemoKit/README.md) | Pure Swift package with one library target | `Sources/DemoKit/ContentView.swift` |
| [DemoApp](DemoApp/README.md) | Ordinary Xcode application with an `App` / `WindowGroup` entry | `Sources/ContentView.swift` |

Open one example folder in VS Code, open its source file, then select
**ContentView** in **Preview > Current File** or use its **Run Preview** CodeLens.
The extension derives its host outside the source project. The project's
OpenSwiftUI dependency supplies the `#Preview` macro and rendering runtime.

The first dependency resolution can download Swift packages and seven binary
XCFramework archives. Use Xcode 26.6 / Swift 6.3. The examples declare macOS 15
and iOS 18 deployment targets; preview destinations are macOS and iOS Simulator.

## Dependency and verification record

`DemoKit/Package.resolved` is generated by `swift package resolve` with the normal
remote dependency configuration. DemoApp's Xcode workspace lockfile is generated
by Xcode package resolution. Both pin OpenSwiftUI-spm `0.24.3` and SwiftSyntax
`603.0.2`; each keeps its own generated `originHash`. Dependency resolution does
not verify preview compilation or execution.

On 24 Oct 2026, all seven official `0.24.3` XCFramework archive SHA-256 values
matched the release manifest and tagged package manifest. Release source:
`8b4306a0`. With Xcode 26.6 / Swift 6.3.3, public SDKs, and fresh module caches,
import and provider API typechecks passed for arm64 macOS 15, iOS Simulator 18,
and visionOS Simulator 2. These checks did not link or run either example, verify
gestures, or add visionOS support to the extension.

## Native acceptance

On 24 Oct 2026, both examples passed automatic integration with Xcode 26.6 /
Swift 6.3.3 on macOS and iOS 26.5 Simulator. Each check used the project's remote
OpenSwiftUI-spm `0.24.3` dependency, compiled the original macro, built the adapted
host, discovered `ContentView`, received native readiness, and stopped the owned
process. The source, project/manifest, and dependency lockfile stayed unchanged.
These automated checks did not inspect the rendered pixels or test input.

For each example and supported destination, check that:

1. The source list finds its unnamed preview with the `ContentView` label.
2. The build uses the project's OpenSwiftUI dependency and original macro expansion.
3. The native window shows the globe image and `Hello, world!` text.
4. Rebuild starts a new preview process and Stop exits the owned host.
5. Source files, project/manifest, and dependency lockfiles remain unchanged.

These minimal views contain no gestures or mutable state. Input, state changes,
and redraw need a separate interaction fixture; readiness alone does not prove
them. The visual and interaction checks remain separate from the automated results.
